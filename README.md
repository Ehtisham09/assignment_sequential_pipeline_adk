# Rabbia Amjad – Ai DataYard Sequential Pipeline Assignment

## Track
**LaunchPad** – a product launch kit built as a 6-agent sequential pipeline using Google ADK and the Gemini API. The user types one product idea, and the pipeline produces market research, customer personas, a product strategy, marketing copy, an HTML landing page, and a QA review.

## Pipeline diagram

```
User product idea
      │
      ▼
1. market_researcher_agent ───────► market_research_output
      │
      ▼
2. persona_builder_agent ─────────► personas_output
      │
      ▼
3. product_strategist_agent ──────► product_strategy_output
      │
      ▼
4. copywriter_agent ──────────────► marketing_copy_output
      │
      ▼
5. landing_page_builder_agent ────► landing_page_output
      │
      ▼
6. qa_reviewer_agent ─────────────► qa_review_output
```

A `SequentialAgent` (`root_launch_pipeline_agent`) runs the six agents in order. Each agent saves its final answer to session state using `output_key`, and later agents read earlier results through `{state_key}` placeholders in their `instructions.txt` files.

## Agent contract table

| # | Agent | Reads (state keys) | `output_key` | Produces | Tools |
|---|---|---|---|---|---|
| 1 | `market_researcher_agent` | user message | `market_research_output` | Market research report | `write_text_file` |
| 2 | `persona_builder_agent` | `market_research_output` | `personas_output` | 3 customer personas + summary table | `write_text_file` |
| 3 | `product_strategist_agent` | `market_research_output`, `personas_output` | `product_strategy_output` | Product name, MVP features, 3 pricing tiers, positioning, 4-week timeline | `write_text_file`, `calculate_pricing` |
| 4 | `copywriter_agent` | `personas_output`, `product_strategy_output` | `marketing_copy_output` | Tagline, hero, 3 feature blurbs, 3 FAQs, CTA, social posts | `write_text_file`, `count_words` |
| 5 | `landing_page_builder_agent` | `product_strategy_output`, `marketing_copy_output` | `landing_page_output` | Responsive single-file HTML landing page | `write_html_file`, `check_html` |
| 6 | `qa_reviewer_agent` | all five outputs above | `qa_review_output` | Scorecard, cross-agent inconsistencies, top 5 fixes, launch verdict | `write_text_file`, `check_html` |

## Custom tools (`tools/file_writer_tool.py`)

| Tool | Used by | What it does |
|---|---|---|
| `calculate_pricing(cost_per_user, margin_percent)` | Product Strategist | Computes a base monthly price from cost and target margin, and suggests Free / Pro / Team prices |
| `count_words(text)` | Copywriter | Counts words to enforce the limits: tagline up to 8 words, blurbs up to 30 words |
| `check_html(html)` | Landing Page Builder, QA Reviewer | Verifies the page has doctype, title, viewport tag, inline CSS, and the hero / features / pricing / FAQ / CTA / footer sections |

## How to run

```bash
cd assignment_sequential_pipeline/starter

python -m venv .venv
.venv\Scripts\activate            # Mac/Linux: source .venv/bin/activate
python -m pip install -e .

copy .env.example .env            # Mac/Linux: cp .env.example .env
# open .env and paste your free Gemini API key (https://aistudio.google.com/apikey)

python check_pipeline.py          # contract check, makes no LLM calls
python agent_runner.py            # terminal run: type a product idea when asked
adk web                           # optional browser UI
```

**Model:** Gemini, `gemini-3.6-flash` by default. It can be changed without editing code by setting `GEMINI_MODEL` in `.env` (for example `gemini-3.1-flash-lite` if the default is overloaded). `GEMINI_DELAY_SECONDS` controls the short pause before each model call, which keeps the run inside the free-tier rate limit.

**Never commit** the `.env` file or the `.venv` folder.

## Reflection

The most important thing I learned in this assignment is how state is passed between agents in a sequential pipeline. Each agent writes its final answer into session state through `output_key`, and the next agents read it by name using placeholders like `{personas_output}` in their instructions. Because of this, the order of agents matters, and a placeholder that points to a key that does not exist yet would break the run. The `SequentialAgent` made this simple, because I only had to list the six agents in the right order.

Writing the instructions was the part that needed the most care. I learned that vague instructions give vague results, so every `instructions.txt` follows the same structure: role, inputs, task, output format, rules, and tool usage. I also made the product strategist the single source of truth for the product name and prices, and told the copywriter and landing page builder to reuse them exactly. That is what lets the QA reviewer check for inconsistencies between agents instead of just praising everything.

The custom tools showed me that an agent can do more than generate text. `calculate_pricing` gives the strategist real numbers, `count_words` lets the copywriter check length limits, and `check_html` lets the page builder and reviewer test the HTML instead of guessing. I also had to tell the agents to return the full document after saving a file, because otherwise a later agent could receive only "saved successfully" and have nothing to work with.

I also ran into practical problems. I had no AWS Bedrock key, so I switched the pipeline to the Gemini API, which only needed the model name and API key to change because all agents use one shared model setting. During testing the model returned a 503 "high demand" error, and I fixed it by switching to a lighter model and spacing out the calls. If I continued this project, I would add a retry step for failed model calls, let the QA agent send feedback back to earlier agents so they can fix problems automatically, and add images to the landing page.
